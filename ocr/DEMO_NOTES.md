# OMR 데모의 자료와 검증 범위

2026-11-11 원본 모션 재사용 및 작업 상태 연결. 본편 4장면과 접힌 부록 2개로 구성한다.

## 공개 시연 자료

- 하바네라 1883년 Choudens 판 스캔: 기존 `habanera_bars5-8.jpg`. 공개 시연을 위해 사용한 자료이며 왈츠 성능 측정 입력과 다르다.
- 사진 효과: `render_bars.py`의 설명용 처리. 실제 휴대폰 촬영본으로 소개하지 않는다.
- 실제 판독: `habanera_omr.mxl`의 P10, 7마디. 첫 음 F4를 G4로 바꾼 두 MusicXML 파일과 SVG를 `build_demo_assets.py`로 만든다. 음높이 하나 외의 음악 데이터가 동일한지 생성 중 검사한다.
- 보정 설명: 같은 판독 결과에 누락된 마지막 F4 하나만 직접 추가한다. 실제 자동 보정 결과가 아니며 다른 리듬·표기 오류는 남아 있다. 이전의 슬러·스타카토·셈여림 추가 그림은 새 데모에서 사용하지 않는다.
- 부록의 음높이 비교는 두 파일의 첫 음(65/67 MIDI)에 대응하는 합성음이다. MuseScore 조작 화면이나 첼로 녹음으로 소개하지 않는다. 수정 전후 MusicXML 다운로드가 가능하다.

## 선택 규칙 확인

비공개 `score-ocr` 저장소의 `7795793`에서 `pick.py`를 읽어 확인했다. 원본 사진·편곡 악보·비공개 코드는 이 저장소로 복사하지 않았다.

1. 시스템별 마디 수를 맞춰 비교할 수 있는 후보를 고른다.
2. 마디의 음 길이가 목표 박자에 맞는 후보를 우선한다.
3. 음높이/쉼표·길이·화음 여부 서명의 일치 수, 같은 음 서명 내 붙임줄 패턴의 일치 수, 입력 순서 순으로 선택한다.
4. 길이가 맞는 후보가 없으면 남은 후보 중 선택하고 해당 마디를 로그에 남긴다. 다수의 판독이 같은 오류를 낼 수 있다.

본편 3장면은 원본의 사진 확대·인식선·행별 칸 채우기·선택 칸 내려오기 모션을 재사용한다. 여섯 행의 사진·칸·선택은 흐름 설명용이며 실제 판독 결과가 아니다. 색은 정답 여부가 아니라 길이 조건을 표현한다. 도식의 선택 패턴은 원본의 고정 난수 예시를 유지하며 실제 `pick()` 실행 결과로 소개하지 않는다. 실제 선택은 위의 길이·후보 일치·입력 순서 규칙을 따른다. 여섯 썸네일 역시 이번에 여섯 번 인식한 증거가 아니다.

## 다시 만들기

```text
python ocr/build_demo_assets.py
python render_cards.py ocr
python fx_check.py ocr.html
python make_video.py ocr --sfx --sfx-db -10 --bgm music/habanera_quartet.wav
python build_site.py
```

SVG 생성은 [Verovio 6.0.0 브라우저판](https://www.verovio.org/javascript/6.0.0/verovio-toolkit-wasm.js)을 빌드 때만 사용한다. 배포 페이지에는 생성된 SVG와 MusicXML만 포함한다. 브라우저용 생성 방식은 Windows 네이티브 DLL 설치가 필요 없다.

반주는 기존 `make_bgm.py`의 4파트·음표·템포·음량을 유지한다. 길이가 더 필요하면 마지막 8마디(12–19)를 반복하고 영상 끝에서 페이드한다. 이번 렌더는 [js-synthesizer 1.11.0](https://github.com/jet2jet/js-synthesizer) / FluidSynth 2.4.6 WASM과 [MuseScore 4.4.4의 FluidR3Mono_GM.sf3](https://github.com/musescore/MuseScore/blob/v4.4.4/share/sound/FluidR3Mono_GM.sf3)를 사용했다. 이전 PC의 FluidR3 GM SF2와 악기 렌더링이 완전히 동일하다고 보장하지 않는다.

```text
python ocr/bgm_events.py events.json --seconds 52
node ocr/render_bgm.cjs <js-synthesizer 폴더> <FluidR3Mono_GM.sf3> events.json music/habanera_quartet.wav
```

음원 원본·SoundFont·설치 패키지는 공개 저장소에 포함하지 않는다. 오디오 트랙·음높이·피크 검사는 실제 청취 평가와 구분해서 보고한다.

### 도넛 모션 1차 복원 기록 (`53f53d8`)

사용자 피드백에 따라 `8094167`의 SVG 도넛을 복원했다. 12시 방향에서 시작하는 고정 길이의 둥근 호, 1.4초당 한 회전, `cubic-bezier(.6,.08,.4,.92)` 가감속을 유지한다. 새 장면에 맞춰 표시 시간만 1장면 1.4초, 2장면 1.6초로 설정했다(공통 재생 배속 적용 전). 고리와 완료 체크는 같은 위치를 사용한다.

이전 CSS와 모션 선언 일치, 두 장면의 회전 중간 상태 및 완료 전환을 확인했다. 이 검사는 움직임의 시각적 자연스러움을 보증하지 못했고, 이후 사용자에게 속도와 궤도 모두 부적절하다는 피드백을 받았다.

복원본 검수: 웹 재생·영상 시계 4장면 통과, 최종 MP4의 회전 중간 프레임 8개와 웹 대조 통과. 디코딩한 오디오는 직전 공개본 `71a85d2`와 해시가 동일하다. 영상은 45.1초 / 1353프레임을 유지한다.

### 이전 조정 기록: 회전 속도와 처리 시간 분리 (`957f0d7`)

- 회색 고리와 SVG는 회전하지 않고 짙은 호만 중심 `(11, 11)`에서 회전한다. 상위 처리 영역의 이동 애니메이션도 페이드로 바꿔 중심이 움직이지 않게 했다.
- 회전 주기는 CSS 1.8초, 가감속은 `cubic-bezier(.42,0,.58,1)`. 처리 구간 `--t`는 각각 1.4초와 1.6초로 별도 설정한다. 공통 재생 배속은 1.15다.
- 회전 반복 횟수는 `처리 시간 / 회전 주기`의 소수 값을 사용한다. 한 바퀴를 채우려고 처리 구간을 늘리지 않으며, 처리 완료 시 그 위치에서 체크로 전환한다. 유한한 반복 횟수로 영상 렌더러의 장면 길이 계산도 유지한다.
- 두 구간 모두 중심 좌표 고정을 확인했다. 종료 시 회전량은 각각 약 323도와 351도로 서로 다르다. 이전 한 바퀴 기준 조정은 사용자에게 너무 느리다는 피드백을 받았다.
- 결과 등장과 음표 변경·소리 시각을 늘리기 전으로 되돌렸다. 음표 이미지 전환과 ‘한 칸 위로’ 표시 및 클릭 효과음의 시각이 일치한다.
- 실제 움직임에 대한 사용자의 판단은 코드/프레임 일치 검사와 별개다. 이전 코드 복사나 검사 통과만으로 모션이 만족스럽다고 단정하지 않는다.

당시 산출물: 45.1초 / 1353프레임. 최종 MP4의 도넛 중간 프레임 8개와 웹을 대조했고, 네 장면 끝은 카드와 일치한다. 디코딩한 오디오는 `71a85d2` 공개 영상과 해시가 동일하다. 오디오 피크 약 0.294, 내부 파일 연결 130개 확인.

## 현재: 원본 재사용 및 작업 중 상태 연결

기준은 `0b219fd`의 원본 HTML이다. 원본의 카메라 스캔선, 도넛 SVG와 회전, 단계 이름 전환, 한 마디 스캔, 사진 확대와 칸 채우기·내려오기, 결과 막대를 재사용한다. 원본은 `references/ocr-20261105/`에 보존했다. 원본의 회전 주기·가감속·공통 배속은 바꾸지 않았다. 장면 끝 대기는 원본의 3000ms다.

- 첫 장면은 원본의 2.2초 처리 시작과 6.4초 결과 등장을 유지한다. 결과가 나타났다고 완료 체크를 띄우지 않는다. 상태를 `원래 음 확인 중` → `음표 편집 예시` → `바뀐 소리 확인 중`으로 이어간다. 6.9초에 원래 음, 7.8초에 편집, 8.6초에 바뀐 음을 보여 주고 9.5초에 `예시 확인 완료`로 바뀐다. 이 시각들은 공통 1.15배속 적용 전 값이다.
- 도넛 표시 구간만 첫 장면 2.2–9.5초, 두 번째 장면 1.7–8초로 연결한다. 반복 횟수는 해당 구간 / 원본 회전 주기 1.4초다. 회전 수에 맞추려고 작업 시각을 늘리지 않는다.
- 두 번째 장면도 판독 결과 등장, 빠진 음 강조, 보완 예시 표시까지 작업 중이다. 실제 판독과 직접 편집한 설명용 결과의 구분을 유지한다. 예전의 슬러·스타카토·셈여림 보완 그림은 재사용하지 않는다.
- 원본의 모션을 재사용하되, 합의한 실제 파일 편집·다운로드 부록과 왈츠 검증 범위 표기는 유지한다. 별도 라이브러리를 도입하거나 기존 CSS를 GSAP으로 옮기지 않는다.

검수: 원본 키프레임 9개와 회전 중간 상태를 대조했다. 결과가 나타난 뒤에도 작업 중 문구와 회전이 유지되고, 마지막 동작 뒤에만 체크가 나오는지 확인했다. 다시 재생했을 때 완료 상태가 초기화되는지, 음표 이미지 변경과 효과음 시각이 맞는지도 확인했다. 웹/영상 시계 4장면 및 부록 조작·모바일 레이아웃 검사 통과. 최종 MP4 검수 결과는 아래에 기록한다.
