# 장면 설계 예시

새 데모나 큰 재설계를 할 때 읽는다. 아래 예시는 설계 방법을 설명하는 가상 장면이다. 특정 프로젝트의 구현·운영 증거로 인용하지 않는다.

## 먼저 대표 장면 하나로 확인한다

전체를 같은 템플릿으로 채우기 전에, 관람 목적을 가장 잘 보여주는 장면 하나를 만든다. 무엇을 입력했고 무엇이 달라졌는지 화면만으로 이해되는지 확인한 뒤 확장한다. 원문 인용 중심 장면과 실제 앱 조작 장면을 같은 틀에 억지로 맞추지 않는다.

입력 자료의 범위와 결과가 정해지면 다음 항목을 짧게 적는다. 모든 작업에 긴 기획서를 요구하지 않는다.

| 항목 | 적을 것 |
| --- | --- |
| 관람자와 목적 | 누가 보고 무엇을 이해해야 하는가 |
| 필요한 출발점 | 이 장면이 시작될 때 알아야 할 최소 맥락 |
| 입력 | 화면에 보이는 구체적인 문서·사진·요청 |
| 처리와 사람의 행동 | 무엇이 자동이며 어디서 선택·승인이 필요한가 |
| 결과 | 무엇이 바뀌고, 앞의 무엇과 비교할 수 있는가 |
| 증거 성격 | 실제 화면, 예시 데이터, 재현, 설명용 중 무엇인가 |
| 화면에 남길 것 | 비교에 필요한 입력·이전 결과·최종 상태 |
| 시간 | 등장·처리·읽기·전환을 각각 어떻게 확인할 것인가 |
| 합격 기준 | 시청자가 답할 수 있어야 하는 질문 또는 관찰할 변화 |

## 예시 A: 견적서를 업무 기록으로

**이해할 내용:** 문서가 기록으로 옮겨지며, 저장에는 사람의 확인이 필요하다.

1. 견적서가 들어오고 요청 “이 견적서 입력해 줘”가 보인다.
2. 품목·수량·금액의 원문을 차례로 강조한다. 대응하는 입력칸이 채워진다.
3. 값이 모두 채워지면 원문과 입력 결과를 함께 남겨 비교할 시간을 준다.
4. 사람이 확인 버튼을 누르는 장면 뒤에 저장 결과가 나타난다.
5. 완료 표시는 “입력 완료”처럼 실제 확인한 범위로 쓴다. 결제·납품까지 끝났다는 인상을 주지 않는다.

한 장면으로 묶어도 네 단계가 보이면 충분할 수 있다. 매 단계마다 별도 제목 슬라이드를 추가하지 않는다. 자동 저장 시스템이라면 사실에 맞게 바꾸며, 보기 좋게 만들려고 승인 단계를 창작하지 않는다.

## 예시 B: 사진에서 읽고, 틀린 곳을 고치기

**이해할 내용:** 사진 판독 결과가 원본과 달라 추가 처리가 필요하다.

1. 손으로 입력하기 번거로운 원본 사진과 만들어진 파일을 보여준다.
2. 원본의 한 부분과 1차 판독의 어긋난 부분을 함께 확대한다. 제목 없이도 차이가 보이게 한다.
3. “AI 사진 인식” → 결과, “음·리듬 수정” → 결과, “빠진 표시 보완” → 결과를 필요한 범위에서 이어 보여준다.
4. 각 처리는 짧은 진행 상태를 거치되, 결과를 읽는 시간은 별도로 둔다. 이전 결과를 남겨 무엇이 고쳐졌는지 비교하게 한다.
5. 실제 결과가 없는 단계는 그 장면에 “설명용 예시”를 표시한다. 시연을 위해 그린 개선 결과를 측정 성과로 쓰지 않는다.

여러 사진을 비교하는 장면은 사진들을 실제로 펼쳐 보여주고 각 판독 결과를 남긴다. 불투명도 변화만으로 “다시 읽었다”는 뜻을 표현하지 않는다. 작은 악보나 표의 차이를 못 알아보면 문장을 추가하기 전에 비교 영역을 키운다.

## 예시 C: 통화에서 할 일로

**이해할 내용:** 특정 발언이 특정 업무 후보가 되고, 사람이 저장한다.

1. 통화 또는 녹음의 존재를 짧게 보여준다.
2. 파형에서 추출된 문장을 보여준다. “내일 샘플을 보내 주세요”처럼 목적어와 행동이 있어야 한다.
3. 해당 문장에서 할 일 후보로 화살표가 이어진다. 원래 문장은 남겨둔다.
4. 사람이 저장을 선택하면 후보가 등록된 업무로 바뀌고 식별 번호가 남는다.
5. 나중에 보고에 다시 등장하면 기존 보고 영역을 유지하고 해당 줄만 한 번 강조한다.

업무 등록 완료, 작업 수행 완료, 실물 수령 완료는 서로 다르다. 완료 체크와 문구가 어느 상태를 가리키는지 맞춘다.

## 입구와 PDF 연결

- 대표작은 실제 화면 썸네일과 “문서의 항목이 입력칸으로 옮겨지는 과정”처럼 볼 내용을 설명한다.
- 추가 작품은 대표작과 구분한다. 대표작 개수는 분량과 목적에 맞추며 고정하지 않는다.
- PDF는 결과 화면과 본인의 판단을 빠르게 훑게 하고, 데모는 처리 과정을 보여주는 데 사용한다.
- 설명 제목·말풍선·캡션이 이미 들어간 데모 카드 전체를 PDF에 다시 넣으면 설명과 여백이 중복될 수 있다. 원본 화면의 필요한 부분을 사용하는 방안을 먼저 본다.
- PDF의 해당 사례에서 연결할 때는 공통 목록 첫 화면보다 그 사례의 시작점으로 연결한다. 장면 링크가 지원되는지 실제로 확인하며 작동하지 않는 링크를 만들지 않는다.

## 자주 생기는 오해

| 요청 | 피할 해석 | 적용할 판단 |
| --- | --- | --- |
| 글을 줄여 달라 | 목적어·맥락까지 삭제 | 중복을 지우고 화면에서 과정을 보이기 |
| 결론부터 말하지 말라 | 모든 제목 금지 | 장면 없이 이해 못 할 결론과 과장을 피하기 |
| 숫자가 어렵다 | 수치 전부 삭제 | 무엇을 센 값인지 실제 대상과 연결 |
| 장면을 줄여 달라 | 처리 단계를 건너뛰기 | 연결 과정은 보존하고 반복 장면을 합치기 |
| 좀 빠르게 | 전체 배속 올리기 | 전환·장식을 줄이고 읽는 시간은 보존 |
| 강조해 달라 | 반복 깜빡임·확대 | 필요한 순간에 한 번, 충분한 대비로 |
| 결과부터 보여 달라 | 원인과 입력을 영원히 생략 | 결과로 관심을 끈 뒤 최소 맥락과 과정을 연결 |
