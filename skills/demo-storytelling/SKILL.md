# 이해되는 데모 만들기

**설명 문장을 줄인 자리를, 알아볼 수 있는 과정으로 채운다.**

목표는 짧은 문구나 많은 애니메이션이 아니다. 처음 보는 사람이 무엇을 넣었고, 도구가 무엇을 했으며, 결과가 어떻게 달라졌는지 화면에서 따라갈 수 있게 한다. 이 저장소의 데모 제작·검수 과정에서 반복된 피드백을 일반화한 기준이다. 특정 색상, 폰 비율, 곡, 장면 수를 공통 규칙으로 강제하지 않는다.

## 작업 범위와 읽을 자료

- 새 제작·재설계: 아래 기준과 [장면 설계 예시](references/scene-design.md)를 읽고, 대표 장면부터 만든다.
- 기존 데모 평가: [최종 산출물 검수](references/artifact-review.md)를 읽고 실제 관람 경로와 재생본을 확인한다. 평가만 요청받았다면 파일을 수정하지 않는다.
- 특정 결함 수정: 해당 구간과 영향을 받는 전환·출력 형식만 확인한다. 전체 디자인을 자동으로 다시 만들지 않는다.
- 최종 전달 전: 최종 산출물 검수의 완료 기준을 적용한다. 소스 수정과 실제 출력 확인을 구분한다.

사용자가 선택한 매체와 이야기 방향을 존중한다. PDF는 독자가 멈추고 훑을 수 있고, 영상은 제작자가 보여주는 시간을 결정한다. PDF의 문장을 줄였다는 이유로 영상의 연결 과정까지 삭제하지 않는다.

## 판단 순서

1. **사실과 증거**: 실제 작동 범위·수치·사용자를 맞춘다. 연출을 구현 완료의 증거처럼 보이지 않게 한다.
2. **처음 보는 사람의 이해**: 대상, 요청, 처리, 결과와 사람의 개입이 이어지는지 본다.
3. **관람 경로**: 무엇부터 보고 어디로 이어지는지 정한다. 대표작과 추가 자료의 비중을 구분한다.
4. **읽는 시간과 움직임**: 정보가 나타난 뒤 이해할 시간, 시선의 이동, 전환을 조절한다.
5. **시각·음향 마감과 출력 확인**: 대비·정렬·화살표·음원·효과음·반복 재생을 실제 전달 파일에서 확인한다.

이는 제작·수정의 우선순위다. 글자가 안 읽히거나 소리가 설명을 덮는 등 이해를 방해하는 마감 결함은 뒤로 미루지 않는다.

## 1. 증거와 관람 경로부터 정한다

시청자, 전달 매체, 보고 나서 이해하거나 할 행동을 기존 자료에서 확인한다. 빠진 정보가 결과를 크게 바꿀 때만 질문한다. 사실관계가 충돌하면 수치를 임의로 고르지 말고 해당 주장을 보류하거나 확인한다.

화면의 성격을 근처에 짧게 표시한다.

- 실제 운영 화면: 식별 정보를 가렸는지 확인한다.
- 실제 앱 + 예시 데이터: 데이터는 예시지만 앱 동작은 실제임을 구분한다.
- 재현 화면: 언제 무엇을 다시 재현했는지 밝힌다.
- 설명용 도식·애니메이션·구상안: 구현되거나 실측된 결과와 구분한다.

같은 입력을 다시 보내 찍은 화면도 과거 실운영 캡처와는 다르다. 예시 데이터 표시는 미구현 기능까지 실제 동작으로 소개해도 된다는 뜻이 아니다. 회사 자료나 개인 정보를 설명용 샘플에 복사하지 않는다.

성과 수치는 단위·대상·조건·분모를 이해할 수 있을 때 쓴다. 코드에서 특정 경로를 못 찾았다는 사실을 오류 발생 0건이나 재발 방지 완료로 바꾸지 않는다. 일부 질문의 성공을 전체 업무의 성공으로 확대하지 않는다. 근거가 다른 화면과 수치를 같이 놓으면 그 관계를 표시한다.

여러 프로젝트를 보여주는 입구에서는 대표작부터 안내한다. 실제 화면 썸네일, 무엇을 볼 수 있는지 한 문장, 바로 열리는 링크를 사용한다. PDF에서 이어지는 링크는 가능한 한 해당 작품이나 장면으로 연결한다. 모든 작품을 같은 비중으로 나열하거나 강한 작품을 목록 끝에 묻지 않는다. 녹화·테마 시안 선택 같은 제작용 조작은 관람 화면에서 분리한다.

## 2. 글은 줄이고 이해에 필요한 맥락은 남긴다

장면마다 시청자가 알아볼 변화 하나를 정한다. 제목·본문·캡션·숫자 카드가 같은 사실을 되풀이하면 하나만 남긴다. 이를 위해 입력 대상, 요청의 목적, 결과의 의미까지 생략하지 않는다.

- “이거 입력”보다 “이 견적서 입력해 줘”처럼 대상과 행동을 남긴다.
- 내부 이름·업계 약어는 첫 등장에 역할을 붙인다. 새 별명을 이해시키는 데 장면을 쓰지 않는다.
- “132 → 126”만 보여주지 않는다. 무엇의 개수인지, 무엇이 달라졌는지 실제 항목이나 결과와 연결한다.
- “사진 탓이 아니라 숫자 때문”처럼 맥락 없는 결론을 먼저 선언하지 않는다. 사진과 어긋난 결과를 먼저 비교하게 하거나 “어려웠던 점”처럼 중립적인 제목을 쓴다. 제목이 필요 없으면 생략한다.

숫자·제목·결론을 일괄 금지하지 않는다. 결과부터 보여주는 광고형 구성도 가능하다. 단, 눈앞의 증거가 제목을 이해하게 해야 하며, 초안을 완성본처럼 말하는 등 검증 범위보다 강한 표현을 쓰지 않는다.

## 3. 움직임이 과정을 설명하게 만든다

한 물건·문서·메시지를 따라가게 한다. 필요한 맥락만 짧게 둔 뒤, 입력 → 처리 → 결과의 변화를 같은 장면 안에서 연결한다. 배경 설명을 모두 읽어야 첫 작동 장면에 도달하는 구성을 피한다.

- 원문에서 처리되는 항목을 강조하고, 대응하는 입력칸이나 결과로 이동시킨다.
- 처리 중에는 이해 가능한 단계 이름과 로딩 상태를 보여준다. 끝나면 실제 결과가 남게 한다.
- 수정 과정을 보여줄 때 원본과 이전 결과를 필요한 동안 유지한다. 단순히 진하기만 바꾸는 것으로 변화의 의미를 전달하려 하지 않는다.
- 합계가 중요하면 개별 항목이 합계로 이어지는 과정을 보여준다. 숫자가 뛰었다는 사실만 보여주지 않는다.
- 사람의 저장·선택·승인이 필요한 곳을 자동 처리와 구분한다. 초록 체크는 무엇이 완료되었는지 설명할 수 있을 때 붙인다.

장면을 합칠 때는 반복을 제거한다. 이해에 필요한 중간 단계는 남긴다. 시작 전의 빈 화면이나 지엽적인 구현 설명이 관람 목적에 기여하지 않으면 뺀다. 장식용 동작은 정보 전달을 돕는 경우에만 추가한다.

## 4. 읽는 시간과 이동 시간을 따로 조절한다

정보 카드가 나타나는 속도, 읽도록 머무는 시간, 화살표·전환 속도를 독립적으로 다룬다. 전체 재생 배속을 올려 모든 장면을 한꺼번에 빠르게 만들지 않는다.

- 새 정보가 나타나면 그 내용을 이해할 시간을 준다. 다음 카드가 앞의 내용을 덮거나 시선을 빼앗지 않게 한다.
- 화살표와 장식 전환은 불필요하게 기다리게 하지 않는다. 정확한 시간은 실제 글의 양과 재생 화면으로 결정한다.
- 비교에 필요한 앞선 결과는 남겨둔다. 다시 언급하는 순간에만 한 번 강조한다.
- 자동 재생 웹 데모에는 이전·다음·정지 등 필요한 관람 조작을 둔다. 정지 버튼이 장면 넘김만 멈추는지, 내부 움직임도 멈추는지 실제 동작과 표기를 맞춘다.
- 글자를 흐리게 하거나 축소해서 정보를 우겨 넣지 않는다. 작은 화면에서도 제목과 핵심 결과가 읽혀야 한다.

## 5. 실제 산출물로 완료를 판단한다

최종 검수는 [검수 절차](references/artifact-review.md)에 따른다. 먼저 처음 보는 사람이 이해하는지 확인하고, 다음으로 화면·움직임·음향이 의도대로 나오는지 확인한다.

HTML 미리보기, 카드 PNG, MP4, 배포본 중 실제 전달할 형식을 검사한다. 정지 화면은 움직임을 증명하지 않고, 코드나 오디오 파형은 실제로 들리는 소리를 증명하지 않는다. 검수할 수 없는 항목은 미확인으로 남기며, 사람이나 다른 평가자가 이해했다고 꾸며 쓰지 않는다.

전달할 때는 바뀐 핵심, 산출물 링크, 직접 확인한 형식·범위, 남은 한계를 짧게 보고한다. 파일을 만들었다는 사실과 실제 업로드·배포 완료를 구분한다. 공개 범위는 해당 작업에서 받은 권한을 따른다.
